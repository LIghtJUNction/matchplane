# ADR 0019：使用 PostgreSQL 恢复 Valkey 订单簿投影

- 状态：已接受
- 日期：2026-08-24

## 背景

Valkey 保存可重建的订单簿读模型。PostgreSQL 会在提交每条撮合命令及其 outbox 消息的同一事务中，持久化完整的 `order_book_delta`。每条 delta 都是完整订单簿替换，而不是增量补丁。

原投影器只接受连续序列。Valkey 被清空后，只要下一条 Kafka 记录的序列大于 1，投影器就会判定存在缺口并退出；重启后仍会读到同一条记录，形成永久崩溃循环。没有后续记录的空闲市场也无法自行暴露缓存缺失，会一直不可用。

在这里回退 Kafka 不是合适的修复手段：保留期可能短于所需历史，回放成本会随主题历史增长，而持久数据库已经保存了更新的完整替换状态。

## 决策

1. `domain_events` 中 `stream_kind = 'order_book_delta'` 的 PostgreSQL 记录是 Valkey 衍生投影的权威恢复来源。
2. 存储层读取某市场的最高序列，并在返回前校验行序列、市场身份、状态哈希编码和确定性 Protobuf 载荷哈希。
3. Valkey 提供原子修复操作：它可以跳到更新的持久完整替换，也可以覆盖不完整的 sequence/JSON 键对；若缓存中已有相同或更新序列的完整投影，则该投影胜出，从而围住延迟修复者。Lua 直接精确比较序列字符串，不将其转换为 IEEE-754 数字。
4. 连续应用报告缺口时，投影器从 PostgreSQL 修复，再提交触发恢复的 Kafka offset；后续已被覆盖的记录按重复消息处理。
5. 已认证的 Gateway 在市场投影缺失或损坏时按需修复，因此即使空闲市场在缓存丢失后没有新 Kafka 流量，也能恢复。若 Valkey 暂时不可用，接口可以直接返回已校验的持久投影。
6. 为 `(market_id, shard_sequence DESC)` 增加部分 PostgreSQL 索引，使最新投影查询有界，同时不索引无关事件流。

## 影响

- Valkey 丢失不再需要回退 Kafka 或人工灌入缓存。
- PostgreSQL 仍是事实来源；缓存修复不会根据未经校验的本地值编造状态。
- 投影器新增 PostgreSQL 连接依赖，但仅在恢复时查询。
- 投影器与 Gateway 并发修复是安全的，旧的完整投影不能覆盖更新投影。
- 因为 delta 是完整替换，恢复成本与当前订单簿大小相关，而不是与保留的事件历史长度相关。
- PostgreSQL/Kafka 分歧和畸形 Kafka 记录隔离仍是独立的可靠性问题；本决策不会掩盖它们。
