# ADR 0013：子平台拥有的向量检索

## 地位

公认

## 语境

嵌入模型、向量维度、索引调整、隐私策略和检索基础设施
每个垂直领域都以不同的速度变化。将根控制平面绑定到一个向量
数据库使每个子平台为它可能不使用的实现付费，并将其转变为内部
优化为公共兼容性承诺。

## 决定

1. 子平台可以拥有自己的嵌入和向量检索实现。根合约是
   `matchplane.retrieval/v1`，不是 pgvector、Qdrant、Milvus、Elasticsearch、模型名称或
   距离度量。
2. 检索边界传输有范围的请求和有界的规范根资产 ID
   分数/原因。它从不传输原始向量或提供者凭证。
3. 根对租户/域范围、资产状态、成员资格、确定性保持权威
   政策、曝光计费、介绍、联系同意、付款和审计。检索是
   是建议性的并且不能改变这些状态。
4. 提供者端点和秘密引用是部署配置。包清单可能
   声明协议所有权，但它不能使根获取任意 URL。
5. 现有的根 pgvector Worker 和 `/v1/embeddings` API 仍然是兼容性提供者，同时
   部署迁移。新的子平台不得依赖于根的数据库扩展；他们
   仅依赖于版本化检索合约。

## 结果

- 垂直行业可以选择本地或托管索引，并无需根即可升级其嵌入模型
  迁移，前提是它保持协议和规范 ID 稳定。
- 根部署可以保留简单的 PostgreSQL 权限并避免跨域暴露向量
  子平台边界。
- 候选响应必须被视为不可信建议：根重新检查范围和当前
  说明并记录提供者/版本。
- 在所有活动子平台使用后，可以删除兼容性 pgvector 实现
  协议和迁移是明确版本化的。
