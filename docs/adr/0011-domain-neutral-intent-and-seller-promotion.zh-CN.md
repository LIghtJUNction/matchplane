# ADR 0011：域名中立匹配、同意的联系人交换和卖家促销收入

## 地位

被市场基金会接受；通用意图/报价/介绍内核现在是
新垂直领域的稳定路径，而车辆 API 在迁移过程中仍保持兼容性适配器。

## 语境

MatchPlane的持久价值是需求方参与者和供应商之间的谈判层
供给方参与者。车辆买家和卖家就是一个例子，而不是模型本身。经过一个
介绍成功后，双方可通过微信或电话继续进行交易
依赖于观察平台外销售的佣金并不是可靠的主要收入来源。

## 决定

1.双方使用相同的`marketplace_parties`身份和能力令牌机制。这
   垂直供应标签（`buyer`/`seller`、`requester`/`provider`或另一对），而
   匹配内核使用`demand`和`supply`视角。
2. 垂直领域调整其具体记录以适应领域中立的概念`MatchIntent`，
   `MarketplaceOffer`、`MatchIntroduction`、`ContactChannel`。 Rust 网关保留了
   前三个到 `/v1/marketplace/intents`、`/v1/marketplace/offers` 和
   `/v1/marketplace/introductions`；一场比赛在介绍时存储其得分和原因，以便
   后来的模型更改无法重写历史。
3. 联系交换是一种单独的同意状态转换。需求方创造了
   介绍;供方明确接受联系请求；只有这样双方才可以
   检索对方允许的电话/微信字段。这些值在静态时保持加密状态，
   每个允许/拒绝决定都经过审核。
4. 平台外垂直行业的默认收入策略是卖家资助的促销。供应
   报价可能会附加一个促销活动，定价为固定列表费、展示费、点击费、
   或合格的潜在客户费用。活动和计费曝光事件是平台拥有的记录，并且
   不需要观察最终的离线交易。
5. 租户可以另外启用披露的交易费用或混合政策。这是一个
   明确的配置选择，绝不存在车辆或其他报价中的隐藏价差。
6. 谈判人工智能可以对候选人进行排名、解释原因并提出下一步行动，但它不能
   授予联系人访问权限或将交易标记为完成。这些仍然是经过验证的、可审计的
   状态转换。

## 结果

- 保留当前汽车`vehicle_listings`、`buyer_vehicle_requests`和`offline_deals`
  兼容的适配器。新的垂直行业不需要车辆形状的桌子或流程；他们定义
  通用内核背后有自己的 JSON 模式/检索代理。
- 卖家促销可以在曝光交付时收取，即使买家和卖家离开
  交换联系方式后的平台。
- 未来的约会或服务垂直重复使用身份、同意、审计和收入原语，
  仅更改其架构、副本、排名功能和安全策略。
- 现有预授权交易费租户维持其政策；捆绑演示市场使用
  后付费联系交换，因此无需支付网关即可测试联系流。
