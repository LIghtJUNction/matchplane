# ADR 0012：具有路径范围成员资格的递归平台身份

## 地位

公认。汽车体验是第一个平台节点实例，而不是平台模型。

## 决定

1. 每个平台节点拥有账户，Better Auth认证，范围能力桥，
   联系人加密、审计、支付和匹配接口。当前的部署根目录是
   无父节点；它不会对垂直的演示文稿或列表副本进行编码。
2. 平台节点由诸如`/auto`之类的路径选择，并且其本身可能拥有子节点。路径
   解析为包含其品牌、UI 适配器、架构、排名的租户/域配置
   政策、帐户标签和收入政策。相同的网关和匹配的内核服务于每条路径。
3. 一个平台身份可以声明多个子平台。持久的关系是
   `marketplace_subplatform_memberships (tenant_id, domain_id, party_id)`，具有范围角色
   （`buyer`、`seller`、`both`或范围`admin`）、标签、批准状态和审核时间戳。
   加入`/auto`不会创建第二个帐户。 `admin` 会员资格仅限于此
   平台节点，除非明确的父/子管理关系授予后代访问权限。
4. 平台UI拥有自己的视觉语言、领域字段、过滤器和副本。它调用父/根 API
   使用更好的身份验证身份，并在每个命令中包含选定的域/成员资格范围。
5. 在进行角色敏感操作（发布供应、创建
   需求请求，接受联系方式介绍）已授权。根操作员可以暂停或
   撤销会员资格而不删除帐户或其跨子平台审核历史记录。

## 结果

- 卖家可以在`/auto`中标记为`seller`，在另一个平台节点中标记为`provider`，在一个平台节点中标记为`both`
  第三，无需重复的凭据或联系人。
- Web 构建可以仍然是可替换的平台适配器，而 Rust 服务保持垂直中立。
- 路径路由、成员资格检查和租户/域标识符是安全边界；用户界面标签
  单独永远不是授权。
- 现有的车辆表仍然是一个适配器。新的垂直行业应该添加域架构和 UI 包，
  然后重用根`MatchIntent`、`MatchIntroduction`、联​​系同意和促销/支付 API。
