# ADR 0014：递归平台和组织 API 密钥

## 地位

对于所有新产品行为，均由 [ADR 0015](0015-flat-marketplace-and-stores.md) 取代。这
组织树和 v1 路径仅保留作为授权和迁移兼容层。

## 语境

"根平台"和"子平台"一词描述了部署位置，而不是单独的产品
架构。由另一个运营商安装的平台本身可能承载额外的垂直业务。这
相同的身份、UI 适配器、支付边界、审核规则和注册 API 必须在每个
等级。平台适配器还需要机器凭据，而无需发明其他身份验证
系统。

## 决定

1. 平台节点是一个更好的认证组织，具有可选的`parentOrganizationId`。节点
   没有父级的是当前部署根；孩子可以创建或注册更多孩子
   当其作用范围允许时。
   当部署根挂载到另一个部署时，接收部署会创建一个
   签名的远程节点投影，而不是重新设置源根组织的父级。这让
   源保留其自己的本地根和后代，同时以普通子代的形式出现
   接收树。
2. Better Auth 的组织插件仍然是人类成员资格和角色的权威。这
   在任何祖先管理器对后代进行操作之前，都会检查父关系；目标节点
   数据、支付设置、联系同意和审核历史记录永远不会跨节点合并。
   注册将委派家长经理添加为孩子的所有者/管理员成员，以便
   Better Auth 组织拥有的密钥插件可以强制执行相同的关系，而无需绕过。
3. 机器凭证使用 Better Auth 组织拥有的 API Key 插件和配置 ID
   `platform`、`mpk_`前缀、散列存储、过期、速率限制和显式资源/操作
   权限。 API 密钥不会创建模拟用户会话。
4. 请求必须声明目标组织/平台范围。根验证密钥
   更好的身份验证，检查密钥的组织和平台树关系，然后转发
   范围狭窄的命令。键无法通过元数据或请求正文扩大其自身范围。
5. 密钥轮换为创建新→部署→撤销旧。原始密钥材料仅返回一次并且
   从未存储在清单、日志、浏览器存储或 PostgreSQL 明文中。

## 结果

- 一个平台可以安装在另一个平台下，无需分叉 API 或第二个帐户系统。
- 根操作符可以管理整个后代树，而子操作符仍然受
  注册期间明确授予的关系。
- Better Auth 提供创建、散列、验证、所有权、到期、速率限制和
  撤销； MatchPlane 仅添加平台树授权和域策略。
- 现有运营商承载仍然是内部服务到服务兼容路径
  迁移。新平台适配器应使用组织 API 密钥合约。
