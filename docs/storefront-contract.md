# 商城与店铺接入合约

本文是新接入的产品规范。旧的 `subplatform` API、清单字段和多段路径仅用于 v1 兼容；
新的用户体验和写入都遵循 [ADR 0015](adr/0015-flat-marketplace-and-stores.md)。

## 两层模型

- 商城位于 `/`，拥有品牌、统一账号、公共店铺目录、AI 导购、跨店搜索与比价、联系人同意、
  可选支付、计费和审计。
- 店铺是一个商家的稳定商业身份。每个店铺直接隶属商城，公开地址为单段路径，例如
  `/store-a`。店铺不能再创建店铺。
- `domain` 是商城内部的目录/schema 作用域，不是页面层级；Better Auth organization 是成员
  与权限边界，不是公开商品目录。

## 两种部署方式

商城控制台只把部署方式分成两类：

1. **本地店铺**：Git 仓库或归档会下载到商城环境，经隔离构建后由商城托管。Git 店铺可检查更新；归档店铺可上传新版本。每次更新生成不可变版本，稳定的 `store_id` 和公开地址不变。
2. **在线店铺**：店铺部署在其他服务器，通过受控 API 入驻、签名清单与服务端凭据连接。远程服务提交自己的 URL、目录与检索能力；商城不会要求把远程 API Key 写入浏览器。

`hosted` 仍表示使用商城提供的商品编辑、审核和展示能力；它是店铺的目录实现方式，不是第三种用户可见的部署方式。

上述方式都生成同一类 `stores` 记录。软件包版本和远端绑定可以更新，`store_id` 不变。
新注册的父组织由服务端固定为商城根，浏览器和 API 调用方不能传入另一家店铺作为父级。

## 商品公开核心

每个可公开商品至少包含：

- 商品名称；
- 商品描述；
- 至少一张通过店铺媒体适配器保存的商品介绍图；
- 价格、币种与精度；
- 稳定的店内商品编号；
- 所属 `store_id` 与生命周期状态。

垂直属性可以继续放在受限 JSON 中，但不能替代上述核心字段。店内商品编号唯一；不同店铺
可以使用相同编号。草稿和待审核商品不得进入公共检索。

商城不为新店铺预置商品，也不复制第三方商品页。使用共享编辑器的店主登录“商家中心”，填写商品资料、上传图片并提交审核；平台审核通过后才生成公共商品投影。外部目录只有在商家明确配置并拥有该数据源时才可同步，不能用开发夹具或抓取快照替代商家提交。

## 公共导购与安全边界

匿名访客可以读取店铺目录并提交商品需求。商城先从数据库取得 active/public 店铺白名单，
让 AI 在有界候选中选择店铺，再从根数据库重读 active 商品并进行排序。响应只返回公开商品
投影，不返回联系人、party、tenant/domain、凭据或未发布内容。

外部检索和模型输出都是建议。引介、联系方式交换、支付、发布和权限变更仍需要登录并经过
各自的确定性授权与同意状态机。匿名导购使用不含身份信息的 HttpOnly cookie 做限流和审计。

## 商业条款

商城可以为每家店配置无收费、订阅、成交佣金或二者组合。金额使用整数 minor units，佣金使用
basis points，并具有草稿、启用、暂停和审计版本。支付网关是可选执行通道；没有网关时仍可
使用双方同意后的联系方式交换，不得把付款当作联系方式释放的隐式前提。
