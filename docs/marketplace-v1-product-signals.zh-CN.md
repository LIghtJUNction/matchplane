# Marketplace V1 产品信号

本文档描述了垂直包使用的域中立内核合约。一个包
可以描述车辆、服务、财产、人员或其他供应类型；根平台确实
不要嵌入这些字段或品牌名称。

## 循环

1. 参与者以自然语言的需求或供应消息开始。
2. 平台代理通过活动平台树路由消息。
3.终端包Agent可以提取自己的结构化配置文件并调用自己的MCP/检索
   工具。内核保留了叙述性、不透明的轮廓投影和范围意图。
4. 该包返回规范的报价 ID，并附有原因以及已知的风险/权衡。
5. 根在显示规范报价之前重新验证它。第一个答案的上限为 3
   提供，以便参与者可以在不阅读目录转储的情况下进行比较。
6. 保存、驳回、打开、比较均记录为幂等证据。一键不重写
   参与者简介；包代理决定重复证据如何改变排名。
7. 参与者可以索取联系人介绍。在请求之前，内核会存储一个
   非接触式销售交接快照，以便人们接收现有的上下文而不是询问
   再次提出同样的问题。

## 稳定的内核资源

- `marketplace_intents`：当前的需求/供应叙述和包拥有的 JSON 属性。
  继续与`PATCH /v1/marketplace/intents/{intent_id}`及其乐观的对话
  `expected_version`；不要为每次聊天都创建新的意图。
- `marketplace_intent_profiles`：每个参与者/域一个版本化的不透明配置文件。根
  强制执行租户和域范围，但不解释预算、用例、能源等字段，
  身体风格，或任何其他垂直词汇。
- `marketplace_behavior_events`：仅附加证据（`offer.open`、`offer.save`、
  `offer.dismiss`、`offer.compare` 或包定义的键）。事件是幂等的并且可能带有
  有界原因/元数据对象。
- `marketplace_offer_preferences`：最新的 `saved`、`dismissed` 或 `neutral` 决策
  规范报价。这是一个偏好信号，而不是联系许可。
- `marketplace_sales_handoffs`：包含配置文件/意图的有范围的、非接触式快照
  参与者选择的上下文。联系交换仍然是现有的同意门控
  介绍流程。

## 推荐合约

每个可见的候选人都是一个规范的报价预测。 `reasons`解释为什么被退回；
`risks` 解释限制或需要人工确认的点。用户界面可以翻译该建议
对定性标签进行评分，例如"非常适合/比较适合/一般/不太适合"，但不得呈现
模型分数作为保证或隐藏原因和风险。

检索 ABI 是可选的。包必须声明并操作真正的检索/MCP 适配器
在 root 调用它之前。如果适配器不可用，根可以使用其有界规范
匹配器并且必须显示降级状态；它不得伪造矢量搜索结果。

## 图像和文件

二进制媒体未嵌入内核数据库中。垂直包声明媒体字段
它理解（通常是内容寻址的 URL 或附件引用）并拥有存储
适配器、恶意软件扫描、调整大小和保留策略。卖家可以在聊天中描述商品；
卖家Agent可以调用包裹的媒体MCP工具，然后将返回的引用放入
手动模式编辑器可以查看的草稿属性相同。手册编辑器仍然是
提交前的权限。在包提供该适配器之前，UI 不得暗示
本地文件已上传或索引。

## 代理和 MCP 所有权

买方或卖方代理是稳定资源的调用者。 `marketplace.*` MCP 工具是
传输这些资源，并且仍然需要范围内的参与者能力。一个包拥有
模式提取、嵌入、向量索引、目录同步和排名策略。这
root 拥有身份、范围、生命周期、幂等性、同意和审计不变量。
