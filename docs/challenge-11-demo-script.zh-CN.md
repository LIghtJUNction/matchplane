# 挑战 #11 演示脚本：卖车店铺点击路径

> 挑战链接：https://api.lmm.best/challenges/11
> 演示店铺：**星辰二手车行**（slug `demo-car-shop`，路径 `/demo-car-shop`）
> 面向读者：发布者 / 评审（下称「评审」），以及负责搭建演示环境的操作员

本脚本给出一条可以逐步点击验证的完整路径，覆盖挑战验收的五个关键点：
真实商品浏览、自然语言选货（工具检索而非 RAG）、店铺页、双方同意的联系方式交换、商城设置。

## 0. 操作员准备（一次性，评审无需操作）

依赖见 `README.zh-CN.md`（Rust、Bun、just、Docker Compose）。在仓库根目录执行：

```sh
cp .env.example .env        # 开发配置，已默认 MATCHPLANE_ALLOW_DEMO_BOOTSTRAP=true
just dev                    # 启动 PostgreSQL / Kafka / Valkey / 服务 / web
just migrate                # 应用数据库迁移
./tools/demo/bootstrap-car-shop-demo.sh   # 种入演示卖车店铺与 6 辆在售车
```

引导脚本会输出演示租户 ID（默认 `00000000-0000-7000-8000-000000001100`）。
把它写入 `.env` 的 `MATCHPLANE_ROOT_TENANT_ID=` 后重启 web 服务：

```sh
docker compose --env-file .env -f deploy/compose/compose.yaml up -d web
```

种子内容（与 `tools/demo/car-shop-seed.sql` 一一对应）：

| 车辆 | 品类 | 一口价 |
| --- | --- | --- |
| 比亚迪 宋PLUS DM-i 2023款 110KM 旗舰型 | SUV | ¥126,800 |
| 特斯拉 Model 3 2022款 后轮驱动版 | 轿车 | ¥169,800 |
| 大众 高尔夫 2021款 280TSI DSG 舒适型 | 轿车 | ¥89,800 |
| 丰田 卡罗拉 双擎 2022款 1.8L E-CVT 精英版 | 轿车 | ¥99,800 |
| 理想 L7 2023款 Pro | SUV | ¥259,800 |
| 本田 CR-V 2020款 240TURBO CVT 两驱舒适版 | SUV | ¥132,800 |

种子只创建店铺、商品与图片，不创建任何账号、支付配置或联系方式；
联系方式交换必须由真实注册账号在界面里完成（见第 4 步）。

## 1. 浏览真实商品（首页）

1. 打开 `http://localhost:4173/`。
2. 首屏即「精选在售」商品货架：6 张车辆卡片，含实拍位图、品牌/品类/车况/所在地和一口价。
   商品先于对话入口出现——这是「产品优先、去 AI 味」的直接体现。
3. 任选一张卡片点击 ❤ 点赞，计数实时 +1（写入 `marketplace_offer_likes`，刷新后保留）。
4. 顶部分类条可按「SUV / 轿车」过滤。

## 2. 自然语言选货（工具检索，非 RAG）

1. 回到首页顶部输入框，输入：**「预算 15 万以内的家用 SUV」**。
2. 点击 **「帮我找」**。输入会预填进选货员对话框并直接发起检索。
3. 预期结果：预算被解析为「最高 15 万」，超出预算的 **理想 L7（¥259,800）** 与
   **Model 3（¥169,800）** 被过滤，返回的候选（宋PLUS、CR-V、卡罗拉、高尔夫）都带
   「价格符合预算」等可解释理由；配置 AI 网关后还会进一步按 SUV 品类收窄。
4. 验证「工具检索而非 RAG」：选货员的候选来自服务端实时读取在售商品
   （`web/src/storefront-search.ts` 的确定性查询），不是向量召回的文档片段。
   可以现场佐证：在管理端下架任意一辆车后重新提问，该车立即从候选中消失。

## 3. 店铺页

1. 点击首页「浏览店铺」，或直接打开 `http://localhost:4173/demo-car-shop`。
2. 店铺页展示「星辰二手车行」的介绍（268 项检测、支持第三方复检）与全部在售车辆。
3. 点开任意车辆查看详情：多字段车况事实、描述、价格；AI 店长可以就这辆车继续问答，
   需要时可通知店员介入。

## 4. 联系方式交换（双方同意，不能手填）

联系方式交换只使用 Better Auth 验证过的邮箱/手机绑定，需要两个真实账号：

1. **买家账号**：评审在 `/login` 注册（开发档 `MATCHPLANE_ALLOW_DEMO_BOOTSTRAP=true`
   免 SMTP 即可注册），在「账号 → 身份绑定」里完成邮箱或手机验证。
2. **卖家账号**：操作员用另一账号登录，在首页点「发布商品」开一家托管店铺，
   发布一辆测试车并由管理员审核上架（这一步同时演示了完整的卖家开店流程）。
3. 买家在该店铺会话中对具体车辆发起 **「交换联系方式」**；界面明确提示
   「平台不再接受手填联系方式」。
4. 卖家在卖家工作台收到请求并点击 **「确认联系方式交换」**。
5. 双方各自看到对方**已验证**的邮箱/手机；任何一方拒绝则「没有交换任何联系方式」。

> 注意：种子店铺（星辰二手车行）的卖家侧是种入的供给方记录，没有绑定真实账号，
> 因此这一步请用第 2 点的真实卖家店铺演示，符合「双方账号都完成验证」的验收口径。

## 5. 商城设置（平台负责人视角）

1. 用首个注册账号（开发档下即根管理员）打开 `http://localhost:4173/admin`。
2. 平台就绪面板：确认根租户、根组织、店铺注册状态一目了然。
3. **AI 网关配置**：填入平台自有模型网关（URL / 密钥 / 模型名），面板明确说明
   「工具结果由服务端重新读取；模型不能读取联系方式、密钥或未审核商品」。
   未配置时选货员自动退化为确定性检索，演示不中断。
4. 登录方式：可选启用微信 / 手机号 / 国家网络身份等登录（`.env` 中对应 OAuth 配置）。
5. 商品审核：管理端「商品审核」列表处理卖家新发布的车辆，上架后立即出现在首页货架。

## 6. 验收对照

| 挑战验收点 | 演示位置 |
| --- | --- |
| 首页先看真实商品、可点赞 | 第 1 步 |
| 自然语言描述需求 → 工具检索选货 | 第 2 步 |
| 卖车店铺页与车辆详情 | 第 3 步 |
| 已验证联系方式、双方同意后交换 | 第 4 步 |
| 平台负责人配置 AI 网关 / 登录方式 | 第 5 步 |

## 附录 A：给种子店铺追加车辆（可选）

引导脚本打印过一次性的卖家 API 令牌（只存 SHA-256）。用它可以走公开的通用市场合约
继续发布车辆（发布后仍需管理员审核上架）：

```sh
curl -s -H 'content-type: application/json' \
  -H "authorization: Bearer <seller API token>" \
  -H 'x-matchplane-platform-path: /demo-car-shop' \
  --data '{
    "tenant_id": "<演示租户 ID>",
    "domain_id": "00000000-0000-7000-8000-000000001101",
    "supply_party_id": "00000000-0000-7000-8000-000000001105",
    "external_key": "demo-car-extra-1",
    "display_name": "五菱 缤果 2023款 333KM 豪华型",
    "attributes": {"description": "2023 年上牌，1 万公里", "brand": "五菱", "category": "轿车"},
    "terms": {"amount": "56800", "currency": "CNY", "scale": 0}
  }' http://127.0.0.1:8080/v1/marketplace/offers
```

## 附录 B：重置演示

种子是幂等的，重复执行不会产生重复数据。需要彻底重置时：

```sh
just down
docker volume rm compose_postgres-data   # 名称以 docker volume ls 输出为准
rm -rf deploy/compose/var/hosted-media/<演示租户 ID>
just dev && just migrate && ./tools/demo/bootstrap-car-shop-demo.sh
```
