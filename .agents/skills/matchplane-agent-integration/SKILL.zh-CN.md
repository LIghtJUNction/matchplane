# MatchPlane 代理集成

为买家和卖家使用相同的集成形状。角色改变意图并允许
工具;身份、平台范围、审核和同意规则不会改变。

## 集成工作流程

1. 声明当前的存储路径、参与方和领域中立的叙述。从来不放
   商城请求中的类别特定字段，除非所选商店拥有该架构。
2. 使用 Better Auth 会话进行人工聊天或使用组织 API 密钥进行身份验证
   机代理。将密钥保留在服务器端并仅请求最小的`platform:read`，
   `retrieval:query`，或需要市场许可。
3、呼叫一次商城路线边界。将选定的商店、`source` 和 `degraded` 视为建议
   路由证据，而不是披露联系方式或结算资金的许可。
4. 在每个选定的商店，仅调用其不可变清单所公布的 MCP 工具。这
   商店拥有其目录、矢量存储、嵌入和排名技能；商店永远不会路由到
   其他商店。
5. 返回规范的资产/商家参考资料和可解释的原因。请root验证
   活跃列表状态、卖家授权、曝光计费以及引入前的同意
   派对。
6. 仅在双方同意后才通过平台联系同意流程发布微信/电话/联系人数据
   各方选择加入。成功的人工智能匹配绝不是同意。

## 令牌和失败策略

外部买家/卖家代理为自己的模型调用付费。商城发起的选择已有限
候选、输入/输出、速率和超时限制以及可审核的`cost_bearer: "platform"`
分类帐。不要在循环中重试降级的响应；浮出水面并让调用者决定是否
尝试其他提供商。

使用 [references/agent-envelope.md](references/agent-envelope.md) 作为请求/结果字段，
最小的 MCP 工具合约。规范的 JSON 模式保留在 `docs/agent-mcp-skill-protocol-v1.json` 中，
`docs/platform-routing-protocol-v1.json` 和`docs/retrieval-protocol-v1.json`。
