# 匹配平面 UI

将根外壳和每个安装的子平台视为同一产品表面。根拥有
导航、身份、同意和平台状态；子平台拥有其域副本、字段、
结果，以及清单中的视觉重点。切勿将车辆目录硬编码到
根外壳。

## 工作流程

1. 检查当前的路由、角色、清单、区域设置、主题和之前的身份验证状态
   更改布局或副本。重用现有的通用组件和 API 帮助程序。
2. 读取`PRODUCT.md`、`docs/subplatform-contract.md` 以及相关组件测试。对于视觉
   工作时，还可以使用`impeccable`技能；使用 `anthropic-art` 来获取所要求的编辑/插图
   资产和 `apple-design` 用于材料、运动和响应式形状决策。
3. 保持一项明确的主要行动。聊天输入是公共页面的主要入口；登录，
   注册、同意、付款和管理操作必须保持明确且真实。
4. 保持可见镀铬安静：没有装饰性安全徽章、技术摘要、虚假信心
   百分比或买家/卖家视图中的占位符按钮。移动诊断和功能
   详细信息进入管理员或调试界面。
5. 使用与人类相同的登录/注册界面。通过 auth 和 保留待处理的聊天文本
   仅在有效的 Better Auth 会话后才恢复它。不要添加单独的子凭证存储。
6. 验证键盘焦点、Escape/外部点击解除、加载/错误/空状态、减少
   运动、深色/浅色主题、中文/英文副本和 320px–1440px 布局。一个控件仅
   在声明服务器操作成功的同时更改本地状态是一个缺陷。
7. 运行最小的相关测试，然后在切换之前运行`just check`。不要创建屏幕截图或
   缓存在`/tmp` 中；使用显式忽略的输出目录并报告其大小。

## 交互规则

- 与循环打字机文本相比，更喜欢稳定的标题和微妙的入口过渡。
- 保持标题在窄屏幕上可读；允许自然换行而不是剪裁一行
  营销文案。
- 将帐户、语言和主题控件放在帐户/首选项区域中，并向右对齐；
  在公共导航中隐藏特定于角色的管理链接，并仅在授权时才显示它们。
- 仅当支持 API 和同意政策可用时，才使结果卡可操作。绝不
  公开列表或代理结果中的电话/微信值。
- 通过插件上下文传递 `theme` 和 `locale` 并让子包翻译它自己的
  复制。根代码不得发明子域字段。
